- Загружены четыре дорожных класса: longitudinal/transverse/alligator crack, pothole.

  драйверы и системные настройки не менялись.

Команда `git log -3 --oneline -- JolBaqylauAI` не возвращает коммитов проекта.
Поэтому «последний Git diff» для этих изменений восстановить нельзя. Изменение
0.30 → 0.60 и min_hits 1 → 2 подтверждается сохранёнными строками видео в БД,
текущим исходным кодом и предыдущим отчётом `DETECTION_QUALITY_KZ.md`, а не вымышленной историей коммитов.

## Препроцессинг и фильтрация

- В inference передаётся исходный кадр OpenCV: BGR uint8. Видеокадр заранее не растягивается.
- Ultralytics делает letterbox с сохранением пропорций, BGR→RGB, BCHW и деление на 255.
- Для входа 640×360 фактический tensor: **[1,3,384,640]** при imgsz=640,
  **[1,3,544,960]** при imgsz=960. Shapes записаны forward-hook, а не предположены.
- Боксы возвращаются в координатах исходного кадра. Изменение размера для preview
  в `jobs.py` происходит **после** inference и не объясняет пропуски.
- Фильтра по классам нет: `classes=None`; обычный YOLO NMS остаётся включён.
- Текущий runtime: confidence=0.60, imgsz=640, шаг около 1 секунды, min_hits=2, IoU=0.20.
- При ~29.97 FPS выбирается каждый 30-й кадр. Одиночный бокс не проходит временной фильтр;
  пропавшее обнаружение в промежуточном выбранном кадре разрывает последовательность.
- Временной фильтр не удаляет кандидата из страницы видео: он сохраняет `suppressed`,
  но исключает его из карты/сводки, пока человек не подтвердит.

## Выполненное сравнение

Каждая комбинация порогов **0.10/0.15/0.25/0.40/0.60** и размеров **640/960**
запускала настоящий inference на тех же входах. Сравнивались четыре размеченных
RDD2022 фотографии, три кадра с известным люком и семь кадров `roadtest1.mp4`.
Сохранены **140 аннотированных изображений**.

Дополнительно весь `roadtest1.mp4` просмотрен моделью на 179 выбранных кадрах при
0.10/640, а отрезок **73.073–75.075 с** обработан **покадрово: 60 кадров × 10 комбинаций**.
Отрезок выбран по максимальному низкопороговому pothole-ответу, а не по подтверждённой яме.
Это диагностическая выборка, не независимый benchmark.

Во время сравнений application-level временной фильтр отключён. JSON содержит
выход YOLO **после его собственного confidence/NMS**, но **до** application NMS,
temporal filtering и ручной проверки. Это не сырые logits до YOLO NMS.
Результаты временного фильтра посчитаны отдельно, offline; БД и runtime не изменены.

## Выводы по причинам

1. **Порог:** подтверждённая причина потери известного pothole-примера с score 0.5421.
   В новом видеосегменте при 0.40 и 0.60 боксов нет ещё до temporal filtering.
2. **Пропуск кадров:** ответ на кадре 2231 при 0.25 не попадает в выборку каждого 30-го кадра.
3. **Temporal filtering:** при 0.10/0.15 выбранный одиночный ответ есть, но не проходит min_hits=2.
4. **Неверные веса, class filter, искажённое соотношение сторон:** признаков ошибки не найдено.
5. **Качество и ограничения модели:** остаются существенными. Даже 0.10/960 даёт ложные
   ответы на разметке/салоне и не устраняет известную ошибку с люком. Без точного таймкода
   и согласованной разметки нельзя утверждать, что каждая визуально заметная яма восстановлена
   или что отсутствие её бокса объясняется только порогом.

**Runtime-пороги, разрешение и временной фильтр оставлены без изменений.** Сравнение
не даёт оснований назвать новый универсальный оптимум. Обучение и дополнительные
модели не запускались. Только диагностический метод `predict(..., imgsz=960)` добавлен;
существующий video pipeline по умолчанию продолжает использовать 640.
